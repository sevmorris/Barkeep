**Added**
- **mrk mode.** When the Brewfile you open is in an [mrk](https://github.com/sevmorris/mrk) checkout, Barkeep lets mrk's own `sync` make the decisions, so the window and the command line follow the same rules. Barkeep turns it on when it finds `scripts/sync`, `scripts/check-picker-desc` and `tools/picker/descriptions.tsv` beside the Brewfile. Any other Brewfile works exactly as before.
  - **The Untracked list is sync's list.** It skips the packages in `~/.mrk/sync-ignore`, and its count matches what Dipstick and `mrk-status` show. A new list, **In Brewfile, Not Installed**, shows the entries `sync --prune` would remove.
  - **Add to Brewfile** runs `sync --add`. A cask goes under `## Casks - <Category>`, by the category its app declares, and Barkeep shows where it will go before you add it. A formula asks for its section. The section sheet now offers the Brewfile's existing sections.
  - **Ignore** is new. It adds the package to `~/.mrk/sync-ignore`, so neither Barkeep nor `sync` offers it again.
  - **Remove from Brewfile**, on a package that is not installed, runs `sync --prune`, which also deletes the package's picker description.
  - After any other change Barkeep saves, it runs `check-picker-desc --fix`, so every package in the Brewfile keeps its mrk-picker description.
  - Barkeep never commits. Committing `~/mrk` stays with `mrk-push` and `pushall`, so their secret scan always runs.
  - mrk mode needs an mrk whose `sync` has `--add`, `--ignore` and `--prune` ([sevmorris/mrk#108](https://github.com/sevmorris/mrk/pull/108)). Run `make pull` in `~/mrk` to get it.

**Fixed**
- **A save that fails now says so.** Barkeep showed nothing when it could not write the Brewfile, so a change could be lost without a word. It now shows an alert with the reason.

**Developer**
- In mrk mode, Barkeep runs mrk's scripts one at a time, with the environment of an interactive login zsh and stdin from `/dev/null`, and streams their output into the console. While `sync` rewrites the Brewfile, Barkeep holds its own saves and reloads the file before it resumes them.
- `release.sh` never prunes the newest release for an older macOS, and the shared release files are compared with PasswordGen's and Dipstick's too.
